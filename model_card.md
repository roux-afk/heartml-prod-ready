## 1. Model Details — сведения о модели

### Обзор и решаемая задача

Модель по 13 демографическим и клиническим признакам относит запись пациента
к одному из двух классов: отсутствие (`0`) или наличие (`1`) болезни сердца
в терминах разметки UCI Heart Disease (Cleveland). Это обучение с учителем
для бинарной классификации. Исходные значения целевой переменной `1–4`
объединяются в класс `1`, значение `0` сохраняется.

Целевая переменная описывает наличие заболевания на момент обследования.
Модель не оценивает вероятность инфаркта в ближайшие годы, тяжесть заболевания
или необходимое лечение. Связь исходной разметки с ангиографическим статусом
описана в [документации UCI Heart Disease](https://archive.ics.uci.edu/dataset/45/heart+disease).

## 2. Model Parameters — устройство модели и данные

### Архитектура и обучение

Pipeline из [models.py](src/heart_disease/models.py) выполняет три шага:

1. `SimpleImputer(strategy="mean")` заполняет `NaN` средними значениями
   соответствующих признаков, вычисленными только на обучающей выборке.
2. `StandardScaler()` стандартизирует признаки по параметрам обучающей выборки.
3. `GaussianNB()` оценивает классы по гауссовой наивной байесовской модели.
   Используются параметры библиотеки по умолчанию; подбор гиперпараметров
   и калибровка вероятностей в проекте не реализованы.

GaussianNB предполагает условную независимость признаков при заданном классе
и гауссово распределение каждого признака внутри класса. Эти предположения
приближённые: медицинские показатели могут зависеть друг от друга, а часть
входов является категориальными кодами. Отдельного кодирования категорий нет:
все 13 столбцов проходят одинаковую числовую предобработку.

CLI также сравнивает SVM с RBF-ядром, Logistic Regression, Decision Tree,
Random Forest, LightGBM и XGBoost. Все обучаются на одном разбиении.
По умолчанию сохраняется Pipeline с максимальной **тестовой F1**;
через `--metric` можно выбрать `accuracy`, `precision`, `recall` или `f1`.
ROC-AUC рассчитывается для доступных вероятностных выходов, но не является
доступным критерием выбора в CLI. См. [train.py](src/heart_disease/train.py).

### Training Data / Evaluation Data — данные обучения и оценки

Источник проекта — локальный [data/raw/cleveland.csv](data/raw/cleveland.csv),
CSV без заголовка: 13 признаков и столбец `target`.
Ниже приведены характеристики, проверенные непосредственно по этому файлу.

| Характеристика | Значение |
| --- | --- |
| Число записей | 303 |
| Класс `0` | 164 записи (54,1%) |
| Класс `1` после бинаризации | 139 записей (45,9%) |
| Возраст | 29–77 лет |
| Пол по кодам датасета | `sex=1`: 206 записей; `sex=0`: 97 записей |
| Пропуски | 4 в `ca`, 2 в `thal`; в CSV представлены пустыми полями |
| Разбиение | 80% / 20%: 242 записи для обучения, 61 для оценки |
| Воспроизводимость разбиения | `train_test_split(test_size=0.2, random_state=0, stratify=target)` |

Контрольная сумма SHA-256 локального CSV:

```text
70a023033aaf840596737ad250eea055762ad825036ac73b5b29168dc638c7c2
```

Загрузка, бинаризация цели и выделение признаков реализованы в
[data.py](src/heart_disease/data.py); параметры разбиения — в
[config.py](src/heart_disease/config.py). Балансировка классов, аугментация
и удаление строк с пропусками не выполняются. Импутация и масштабирование
обучаются после разбиения, что предотвращает утечку статистик тестовых данных
в предобработку. Отдельных validation- и внешней тестовой выборок нет.

### Input Format — входные данные

При применении Pipeline принимает числовой `pandas.DataFrame` размера
`N × 13`, где одна строка соответствует одному обследованию пациента.
Имена и порядок столбцов должны соответствовать `FEATURE_COLUMNS`:

| Признак | Содержание и единицы / кодировка |
| --- | --- |
| `age` | Возраст, лет |
| `sex` | Пол в исходной разметке: `0` — женский, `1` — мужской |
| `cp` | Боль в груди: `1` — типичная стенокардия, `2` — атипичная, `3` — неангинозная боль, `4` — бессимптомное течение |
| `trestbps` | Артериальное давление в покое, мм рт. ст. |
| `chol` | Холестерин сыворотки, мг/дл |
| `fbs` | Глюкоза натощак > 120 мг/дл: `1` — да, `0` — нет |
| `restecg` | ЭКГ в покое: `0` — норма, `1` — изменения ST–T, `2` — гипертрофия левого желудочка |
| `thalach` | Максимальная достигнутая ЧСС, уд/мин |
| `exang` | Стенокардия при нагрузке: `1` — да, `0` — нет |
| `oldpeak` | Депрессия ST при нагрузке относительно покоя, числовое значение исходного датасета |
| `slope` | Наклон ST на пике нагрузки: `1` — восходящий, `2` — плоский, `3` — нисходящий |
| `ca` | Число крупных сосудов, визуализированных при флюороскопии: `0–3` |
| `thal` | Код результата исследования: `3` — норма, `6` — фиксированный дефект, `7` — обратимый дефект |

Кодировки сверяются с [описанием переменных UCI](https://archive.ics.uci.edu/dataset/45/heart+disease).
Для `thal` используется значение кода исследования, а не самостоятельный
диагноз «талассемия».

`target` требуется для обучения и оценки, но не передаётся в `predict`.
При инференсе `NaN` заполняются сохранённым imputer; строки вроде `"?"`
или текстовые обозначения категорий нужно заранее привести к числам / `NaN`.
Встроенной проверки медицинских диапазонов и совместимости единиц нет.
Значения вне обучающего распределения не вызывают автоматического отказа.

### Output Format — выходные данные

- `pipeline.predict(X)` возвращает массив из `N` меток: `0` — прогноз
  отсутствия болезни по разметке датасета; `1` — прогноз наличия болезни.
- Для GaussianNB `pipeline.predict_proba(X)` возвращает матрицу `N × 2`
  с оценками вероятностей классов `0` и `1`; `[:, 1]` используется для ROC-AUC.
  Эти оценки не проходили отдельную калибровку и не являются подтверждённой
  индивидуальной клинической вероятностью.
- GaussianNB выбирает класс с большей оценкой апостериорной вероятности
  (для двух классов граница соответствует примерно `0.5`). Отдельного
  клинически подобранного порога и режима «не уверен» в коде нет.

## 3. Considerations — назначение и условия применения

### Intended Use / Users — назначение и пользователи

Основное применение — учебные и исследовательские эксперименты:
сравнение классификаторов, изучение предобработки без утечки данных,
воспроизводимое обучение и пакетное получение прогнозов.
Основные пользователи — разработчики ML и исследователи, анализирующие
данные Cleveland. Место модели в процессе показано в [Model_BPMN.md](Model_BPMN.md).

Потенциальная поддержка медицинского специалиста потребует отдельной
валидации на целевой популяции и проектирования процесса врачебной проверки.
Текущая модель не предназначена для самостоятельной постановки диагноза,
назначения лечения, исключения необходимости обследования, экстренной
сортировки пациентов или решений о страховании и доступе к помощи.

### Factors / Limitations — факторы качества и ограничения

- **Малый объём и переносимость.** В проекте используется историческая
  выборка одного источника Cleveland. Перенос качества на другие клиники,
  страны, периоды и протоколы обследования не проверен; возраст вне 29–77 лет
  не представлен в локальных данных.
- **Доступность обследований.** Признаки включают результаты нагрузочных
  и инструментальных исследований. Применимость до получения таких данных
  не подтверждена; заполнение большого числа пропусков средними может
  скрывать отсутствие необходимой информации.
- **Предобработка категорий.** Усреднение категориальных кодов может давать
  промежуточные значения, не соответствующие реальным категориям.
  Это упрощение текущей реализации, требующее отдельного сравнения
  с обработкой категориальных признаков.
- **Выбор по тесту.** Один набор из 61 записи используется и для сравнения
  семи алгоритмов, и для отчётных результатов. Поэтому он фактически
  участвует в выборе модели; оценка выбранного победителя может быть
  оптимистичной. Нет кросс-валидации, доверительных интервалов и независимой
  итоговой проверки.
- **Подгруппы.** Возраст, пол, тип боли, наличие пропусков и сочетания
  этих факторов могут влиять на ошибки. Метрики по подгруппам не рассчитаны;
  равенство качества для них не установлено. Расовые и другие
  не представленные в 13 признаках группы отдельно не оценивались.
- **Эксплуатация.** В репозитории нет API, пользовательского интерфейса,
  автоматического мониторинга дрейфа, переобучения и маршрутизации пациентов.
  Реализованы обучение, отчёт и применение сохранённого Pipeline из Python.

### Tradeoffs / Ethical Considerations — компромиссы и риски

Ложноотрицательный прогноз может создать ложное чувство безопасности,
а ложноположительный — привести к лишним обследованиям и тревоге.
Поэтому полнота положительного класса важна при обсуждении медицинского
сценария, хотя фактический критерий выбора CLI по умолчанию — F1.
Повышение чувствительности за счёт смены порога обычно увеличивает
число ложноположительных результатов; такой выбор в проекте не исследован.

Дисбаланс представительства групп и исторические особенности данных
создают риск неравномерных ошибок. До применения к людям следует оценить
качество по подгруппам, проверить калибровку и предусмотреть человеческую
проверку результата. Для новых медицинских данных нужны законные основания
обработки, ограничение доступа и исключение идентифицирующих сведений
из публичного репозитория и журналов.

## 4. Quantitative Analysis / Metrics — оценка качества

### Метрики и протокол

Положительный класс — `1`, наличие болезни. Реализация метрик находится
в [evaluate.py](src/heart_disease/evaluate.py). Здесь `TP` — верно найденные
положительные случаи, `TN` — верно найденные отрицательные, `FP` — ложные
срабатывания, `FN` — пропущенные положительные случаи.

| Метрика | Определение | Что показывает |
| --- | --- | --- |
| Accuracy | `(TP + TN) / N` | Общую долю верных ответов |
| Precision | `TP / (TP + FP)` | Долю положительных случаев среди положительных прогнозов |
| Recall / sensitivity | `TP / (TP + FN)` | Долю найденных положительных случаев |
| F1 | `2 × precision × recall / (precision + recall)` | Баланс precision и recall; критерий выбора по умолчанию |
| ROC-AUC | Площадь под ROC-кривой по оценкам вероятности класса `1` | Способность ранжировать положительные случаи выше отрицательных при разных порогах |

Метрики вычисляются на train и test, округляются до четырёх знаков
и сохраняются в `reports/metrics.json`. Для SVM в текущей конфигурации
ROC-AUC не вычисляется: `SVC` создан без `probability=True`, а `evaluate`
не использует `decision_function`.

### Воспроизведение и рекомендации

В окружении Python 3.12 с зависимостями из `poetry.lock`, из корня проекта:

```bash
poetry install
poetry run heart-disease-train
```

Команда обучит все семь моделей, выберет лучшую по тестовой F1 и создаст
`models/model.joblib` и `reports/metrics.json`. При новом запуске следует
сверить `best_model`, параметры запуска, версии зависимостей и контрольную
сумму данных, затем обновить карточку по фактическому отчёту и присвоить
версию обученному артефакту.

До расширения применения нужны независимая оценка на новых данных,
разделение выбора модели и итогового тестирования, анализ подгрупп,
калибровки и ошибок, а также проверка доступности признаков в момент прогноза.
